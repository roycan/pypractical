# Contributing to PyPractical

First of all, thank you for considering contributing to PyPractical.

Whether you are fixing a typo, improving a unit test, sharing a classroom experience, or creating an entirely new assessment family, your contribution helps teachers and students everywhere.

PyPractical is built on the belief that education improves when teachers share their best work openly and generously.

We are happy to have you here.

---

# Before You Begin

Please take a few minutes to read these documents before contributing:

* `DESIGN_PRINCIPLES.md`
* `CURRICULUM_PHILOSOPHY.md`
* `ASSESSMENT_PHILOSOPHY.md`
* `STYLE_GUIDE.md`

These documents explain not only **how** PyPractical is organized, but also **why** it is organized this way.

Understanding the philosophy behind the project is just as important as following the formatting conventions.

---

# Ways to Contribute

There are many valuable ways to contribute.

## Improve Existing Assessments

* Clarify instructions
* Improve stories
* Fix mistakes
* Suggest better examples
* Improve starter code
* Improve teacher notes

---

## Report Issues

If you discover:

* incorrect expected outputs
* unclear wording
* confusing instructions
* broken unit tests
* grading issues

please open an issue.

Small improvements often have a large impact in the classroom.

---

## Create New Assessment Families

New assessment families are always welcome.

Before creating one, ask:

* What learning objective does this family teach?
* Does it introduce only one major new concept?
* Does it fit naturally into the curriculum progression?

Whenever possible, create several equivalent problems within the same family to support teachers with multiple class sections.

---

## Share Classroom Experience

Some of the most valuable contributions are not code.

If you have used a PyPractical assessment in your classroom, consider sharing:

* estimated completion time
* common student mistakes
* questions students asked
* suggestions for improving the story
* improvements to hints or instructions

Real classroom feedback helps improve future versions of every assessment.

---

# Quality Expectations

Every assessment should:

* have a clear learning objective
* tell an authentic story
* use beginner-friendly language
* include complete teacher resources
* support automatic grading
* follow the project's templates and style guide

Before submitting an assessment, please verify that every expected output has been checked independently.

---

# Unit Tests

Every assessment should include a comprehensive unit test suite.

Whenever practical, include:

* basic cases
* boundary cases
* mixed cases
* hidden cases

Hidden tests should never introduce new requirements.

They should only verify that students have correctly implemented the published specification.

---

# Teacher Resources

Every assessment should include:

* teacher solution
* teacher notes
* estimated completion time
* learning objectives
* common mistakes
* difficulty rating

Teaching resources are an essential part of every contribution.

---

# Writing Style

When writing for students:

* prefer clear language over clever wording
* keep instructions concise
* avoid unnecessary technical vocabulary
* use meaningful names
* provide authentic contexts

Good assessment design removes unnecessary obstacles so students can focus on programming.

---

# Respectful Collaboration

PyPractical welcomes contributors from every teaching background and level of experience.

We encourage constructive discussion.

Different ideas often lead to better educational resources.

Please assume good intentions, give thoughtful feedback, and remain respectful in all project interactions.

---

# Our Shared Goal

PyPractical exists to help teachers create meaningful programming experiences for their students.

Every contribution—whether large or small—moves us closer to that goal.

Thank you for helping build a resource that teachers can trust and students can enjoy.

We are grateful that you chose to share your work with the community.


---


# A note to fellow teachers

Many contributors to PyPractical are full-time teachers.

We understand that lesson planning, grading, and school responsibilities often leave little free time.

Contributions do not need to be large to be valuable.

Fixing a typo, improving a hint, correcting a unit test, or sharing a classroom observation can help thousands of future students.
