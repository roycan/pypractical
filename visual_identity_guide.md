# VIS-001 — Visual Identity Guide

**Status:** Draft

**Applies To:** Website, documentation, diagrams, illustrations, presentations, social graphics, and future PyPractical projects.

* * *

# Design Philosophy

PyPractical should not look like software.

It should look like **a carefully crafted educational resource**.

Visitors should feel that they have discovered a trusted handbook rather than a product.

The visual identity should communicate:

-   warmth
-   craftsmanship
-   curiosity
-   clarity
-   longevity

If someone says,

> "This reminds me of a wonderful textbook I wish I had."

then the design has succeeded.

* * *

# Visual Metaphor

The website should feel like

> **Opening an old but well-loved engineering notebook that has been carefully updated for today's classroom.**

## Accent

I'd actually choose **terracotta** instead of amber.

Reason?

Amber often feels "tech."

Terracotta feels

human,

earth,

craft,

classroom.

```
Terracotta

#C96A4A
```

Use sparingly.

Buttons.

Links.

Icons.

Highlights.

# Typography

This is where I want to splurge emotionally.

## Headlines

**Cormorant Garamond**

Not merely serif.

Beautiful serif.

Looks like something you'd find in an old university press publication.

* * *

## Body

**Source Sans 3**

or

**Inter**

I'd actually lean toward

Source Sans 3.

It's softer.

More book-like.

* * *

## Code

JetBrains Mono

Perfect.

* * *

## Quote

Same serif as headings.

Large.

Generous line spacing.

* * *

# Layout

LOTS of breathing room.

I mean LOTS.

Maximum content width

```
900px
```

not

1400px.

Reading matters more than filling the monitor.

* * *

# Cards

Rounded.

Not too rounded.

```
border-radius:12px;
```

Soft shadow.

Like paper resting on a desk.

* * *

# Icons

Outline icons.

Never filled icons.

Simple.

Feather Icons

or

Heroicons Outline.

* * *

# Illustrations

This is where I'd make PyPractical unique.

Don't use random stock photos.

Instead,

editorial illustrations.

Flat.

Textured.

Muted colors.

Think

children's science textbook

rather than

startup landing page.

* * *

# Photography

When using photos,

show

teachers

students

whiteboards

books

discussion

thinking

not

people pointing at holograms.

* * *

# Texture

This is the fun part.

Very subtle paper grain.

Almost invisible.

Maybe

2%

opacity.

Enough to make screens feel less sterile.

* * *

# Buttons

Soft.

Comfortable.

Example

```
background: terracotta;

border-radius:8px;

padding:14px 24px;
```

Hover

Slight darkening.

No bouncing.

No spinning.

No fancy animation.

* * *

# Motion

Motion should communicate understanding.

Not excitement.

Examples

Cards gently appear.

Workflow slowly draws itself.

Specifications fade in.

Nothing should fly around.

* * *

# Diagrams

Handcrafted.

Rounded rectangles.

Gentle arrows.

Muted palette.

Think

engineering notebook

not

PowerPoint.

* * *

# Spacing

If unsure,

add more whitespace.

Whitespace is part of the design.

* * *

# Tone

The website speaks like

an experienced teacher.

Never

marketing.

Never

sales.

Never

"Revolutionary AI Platform!"

Instead

> We think assessments deserve careful engineering.

# Home Page Feeling

The homepage should feel like entering

# The Signature Illustration

I think this should become the symbol of Open Assessment Engineering.

A large oak table.

On it:

A fountain pen.

A laptop.

A Python book.

A notebook.

A printed assessment.

A cup of coffee.

Sticky notes.

A Git commit diagram.

A classroom seating chart.

Everything belongs.

Everything tells a story.

Above the desk,

morning sunlight.

No people.

Only evidence that a thoughtful teacher has been working.

I honestly think this image says more about PyPractical than any logo could.

* * *

# Logo

I wouldn't start with a logo.

I'd start with a mark.

Maybe

a bookmark

inside

an open book

whose pages subtly resemble

```
{
}
```

Python blocks.

Or perhaps a blueprint grid fading into notebook paper.

Simple enough to work at favicon size.

Meaningful enough to grow with the project.

* * *

# One thing I'd add

This is the only thing I'd gently push beyond your proposal.

Every page should contain

one

beautiful quote.

Not many.

One.

Maybe at the top.

Maybe in the middle.

Something like

> _"Teach the student in front of you, not the curriculum in front of you."_

Or

> _"Educational assessments deserve the same engineering discipline that we expect from good software."_

Or

> _"Would we confidently use this in our own classroom tomorrow?"_

Not as decoration.

As orientation.

Like chapter quotes in a good textbook.
