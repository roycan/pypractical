# Curriculum

## The PyPractical Learning Journey

Programming is more than learning syntax.

It is the gradual development of a way of thinking.

PyPractical is organized around that idea.

Every module builds upon the one before it, allowing students to develop confidence through a sequence of achievable challenges.

Rather than asking, "What Python features should students know?", we ask,

> **"What kind of programmer are they becoming?"**

---

# Stage 1 — Thinking Like a Programmer

Students begin by learning the fundamental building blocks of programming.

They learn that a computer follows precise instructions and that programs are built from small, understandable pieces.

### Concepts

* Variables
* Input and Output
* Arithmetic
* Conditional Statements
* Loops
* Functions

### Assessment Families

* Minimum Cost
* Counting and Totals
* Decision Making
* Basic Simulations

At this stage, students learn that programs process information.

---

# Stage 2 — Thinking About Objects

Once students are comfortable writing procedural programs, they begin modeling the real world.

Instead of asking,

> "What should the program do?"

they begin asking,

> "What objects exist?"

Students discover that software can be organized around the things it represents.

### Concepts

* Classes
* Objects
* Attributes
* Methods

### Assessment Families

* TV Recorder
* Library
* Hotel Reservation
* Classroom Equipment
* Student Records

The emphasis is not on complex algorithms.

The emphasis is on recognizing objects and their responsibilities.

---

# Stage 3 — Objects Working Together

Real software rarely consists of a single object.

Students now learn how multiple objects interact.

Collections become meaningful because they represent groups of real things.

### Concepts

* Lists of Objects
* Searching
* Updating Objects
* Object Collaboration

### Assessment Families

* Library Management
* Restaurant Orders
* School Clinic
* Classroom Scheduling

Students begin writing software that resembles small real-world applications.

---

# Stage 4 — Building Better Software

As students become more confident, they learn techniques that make software easier to understand and maintain.

Programming becomes less about writing code and more about designing systems.

### Concepts

* Inheritance
* Polymorphism
* Composition
* Code Reuse

Assessment families focus on software organization rather than larger algorithms.

---

# Stage 5 — Data and Algorithms

Only after students are comfortable creating software do we ask them to improve it.

Efficiency becomes meaningful because students already understand correctness.

### Concepts

* Searching
* Sorting
* Dictionaries
* Files

Students discover that different solutions can solve the same problem with different levels of efficiency.

---

# Stage 6 — Projects

The curriculum culminates in projects.

Projects combine everything students have learned.

Rather than introducing new concepts, projects encourage students to apply existing knowledge creatively.

Students experience the complete software development process:

* planning
* designing
* implementing
* testing
* debugging
* improving

Projects should feel like accomplishments rather than examinations.

---

# The Role of Assessment

Every assessment has a purpose.

Some assessments diagnose readiness.

Some reinforce recently learned concepts.

Some provide opportunities for students to integrate multiple ideas.

Assessment is never separated from learning.

It is part of the learning journey.

---

# Designing for Confidence

Programming can be intimidating.

PyPractical intentionally creates many opportunities for students to experience success.

Small successes build confidence.

Confidence encourages persistence.

Persistence develops skill.

This progression is one of the guiding principles of the curriculum.

---

# The Teacher's Role

Teachers are more than evaluators.

They are coaches, mentors, and designers of learning experiences.

PyPractical aims to reduce repetitive assessment work so teachers can spend more time helping students think, create, and grow.

Technology should amplify good teaching, not replace it.

---

# Looking Forward

Although this curriculum begins with Python, the habits students develop extend beyond a single programming language.

Students learn to:

* analyze problems
* model real-world situations
* design solutions
* test carefully
* improve continuously

These habits form the foundation of lifelong software development.

Our goal is not simply to teach Python.

Our goal is to help students begin thinking like software engineers.
