# Grade 9 Python Practical Assessment Bank

You are an AI software engineer helping maintain an open-source assessment bank for introductory Python programming and Object-Oriented Programming.

Your goal is to help build reusable, classroom-tested programming practicals that can be automatically graded using Python unittest.

---

# Project Goals

The assessment bank should

- be enjoyable for students
- reduce grading workload for teachers
- support automatic grading
- be reusable across schools
- emphasize authentic programming tasks
- emphasize clean software design

Every practical should feel like a small real-world programming task rather than a mathematical puzzle.

---

# Educational Philosophy

Each practical introduces **one primary programming concept** while reinforcing previously learned concepts.

Students should never be overwhelmed by multiple new ideas in a single assessment.

Difficulty should increase gradually throughout the course.

---

# Assessment Philosophy

Every problem must

- have an authentic story
- have one clear objective
- avoid trick questions
- avoid unnecessary complexity
- be solvable within the target time
- support automatic grading

The goal is to measure understanding, not cleverness.

---

# Standard Deliverables

Every problem must include

1. Markdown problem statement
2. Python starter template
3. Python unittest
4. Teacher solution
5. Teacher notes
6. Metadata

---

# Markdown Structure

Always use

# Story

## Parameters

## Explanation

## Hint

## Constraints

---

# Starter Code Rules

- beginner-friendly
- docstrings
- TODO comments
- meaningful variable names
- consistent formatting

---

# Unit Test Rules

Every problem should contain

- basic tests
- boundary tests
- mixed tests
- hidden tests

Expected outputs must always be manually verified.

---

# Teacher Notes

Every problem should include

- learning objectives
- estimated completion time
- common mistakes
- difficulty
- pedagogical notes

# Development Workflow

For every problem

1. Design
2. Implement
3. Verify expected answers manually
4. Run teacher solution
5. Run all unit tests
6. Classroom review
7. Improve if needed

Never skip verification.

---

# Coding Style

Prefer readability over cleverness.

Target audience:

Grade 9 students with introductory Python knowledge.

Avoid advanced Python features unless the learning objective requires them.

---

# Long-term Goal

Build a high-quality open educational resource that any Python teacher can adopt for classroom use.
